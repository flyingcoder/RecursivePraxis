# RecursivePraxis requirements matrix

This is a documentation-only audit of the active product objective. “Verified” means the cited source exists and the stated behavior has direct test coverage; it does not mean the abstract formalism has been empirically validated as a measure of real-world reasoning quality.

| Inspectable reasoning state | Immutable `Session`, sequence, anomaly artifact, D/C state, attractor | `src/kernel/types.ts`, `phasePortrait.ts`, `cli-commands/status.ts` | Verified | The state is abstract; it is not a transcript of hidden model reasoning. |

## Readiness conclusion

The present codebase satisfies the core *control-runtime* claim: it can govern a bounded sequence of typed, named, legal abstract reasoning operators and produce a redacted, semantically replayable trace. It does not yet satisfy stronger claims about autonomous learning, enduring memory, external-world evidence truth, or empirical cognitive improvement.

Tool-host evidence and artifact hashes are now validated at the same boundary as model/router output, which closes the integrity gap this section previously named as the most direct one. The remaining evidence weakness is different in kind: hash *syntax* is checked, but nothing re-derives a hash from the content it claims to describe, so evidence integrity still rests on the honesty of the host that produced it.

The most consequential product-expansion decisions are unchanged: cross-run memory, and what evidence/provenance model would justify `record`, `validate`, `score`, and `revise`. The reserved verbs are not blocked on engineering — three of the four already have working in-session equivalents. They are blocked on a measurement authority that does not exist in the repository. `docs/ALGEBRA_DYNAMICS_SEAM.md` §4 makes the shape of that gap concrete for the first time by measuring what the current effects table can and cannot distinguish; §6 records why the obvious calibration source is not yet sufficient. A `score`/`revise` capability built before that is resolved would report numbers it cannot justify, which is precisely what the fail-closed stance exists to prevent.
